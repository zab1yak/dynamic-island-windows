# Решения

Короткий журнал архитектурных и продуктовых решений. Новое — внизу.

## D-001. Прозрачность для кликов — per-pixel alpha layered window
`AllowsTransparency=True`: ОС сама пропускает клики по пикселям с alpha=0, края сглажены, таймеров нет.
`SetWindowRgn` даёт рваные края и мерцание при пересоздании региона каждый кадр; переключение
`WS_EX_TRANSPARENT` требует опроса курсора и ломает бюджет простоя.

## D-002. Одно окно фиксированного размера
Окно = максимальный размер острова. Анимируются только `StreamGeometry`, `Clip`, `Opacity` и
`RenderTransform`: нет layout-прохода в каждом кадре и нет перемещений окна.

## D-003. Свои пружины + `CompositionTarget.Rendering` только во время движения
Физика пружины живёт в Core и покрыта тестами; в простое подписки на кадры нет.

## D-004. Core собран под чистый `net10.0`
Запрет на WPF и WinRT в Core обеспечивает компилятор, а не договорённость.

## D-005. View модулей — через ResourceDictionary с DataTemplate по типу VM
Контракт Core без WPF-типов, шаблоны создаются лениво, окно не знает о модулях.

## D-006. Регистрация модулей явная (`services.AddXxxModule()`)
Без сканирования сборок и рефлексии. Плагины через `AssemblyLoadContext` — после v0.1.

## D-007. Interop через `LibraryImport`
Архитектор предлагал CsWin32; выбран ручной `LibraryImport`, потому что нужно ~30 функций,
а генератор добавляет зависимость и большой объём сгенерированного кода. Interop одного модуля
живёт в самом модуле (`Interop/`, `internal`).

## D-008. Визуализатор — пиковый уровень CoreAudio, а не FFT
`AudioMeterInformation.MasterPeakValue` реального устройства вывода: на порядок дешевле loopback-захвата
и FFT, для 4–5 мини-полосок достаточно. Это реальный уровень звука, а не имитация.

## D-009. Иконки — Lucide (ISC)
Штриховой стиль ближе всего к SF Symbols, одна толщина, лицензия ISC (совместима с MIT).
Phosphor (MIT) тоже подходит, но шесть весов провоцируют разнобой.
**SF Symbols не используются:** лицензия Apple разрешает их только в приложениях для платформ Apple,
поэтому SVG из `brendanballon/sfsymbols-svg` и подобных репозиториев в проект не добавляются.

## D-010. Шрифт — SF Pro, если установлен, иначе Segoe UI Variable
`FontFamily="SF Pro Display, SF Pro Text, Segoe UI Variable Display, Segoe UI"`. Файлы SF Pro в
репозиторий не кладутся: лицензия Apple запрещает распространение.

## D-011. Таймеры хранят `EndsAtUtc`, время — через `TimeProvider`
Корректно после сна, перезапуска и смены времени; детерминированные тесты с `FakeTimeProvider`.

## D-012. Пользовательские настройки — свой `ISettingsService` + JSON
`IConfiguration` не умеет атомарно писать. Миграции выполняются на JSON-дереве до десериализации.

## D-013. Single instance — Mutex + named pipe с ACL текущего пользователя
Передача аргументов без лишних поверхностей атаки.

## D-014. Сборка self-contained через Velopack
Установка без UAC и отдельного .NET Runtime, обновления дельтами из GitHub Releases.

## D-015. Запись экрана — эвристика по процессам
Публичного API нет; это честно указано в README.

## D-016. Тесты — xUnit v3 на Microsoft.Testing.Platform
В .NET 10 SDK `dotnet test` с VSTest для xUnit v3 больше не поддерживается; `global.json`
включает новый раннер.

## D-017. Коммиты сразу в `main`
Так задано владельцем репозитория в постановке задачи: одна задача — минимум один коммит, сразу push.
План архитектора с отдельными ветками и PR на каждую задачу не применяется.

## D-018. Полноэкранный режим — без опроса
Остров регистрируется как app-bar (`SHAppBarMessage(ABM_NEW)`) и получает `ABN_FULLSCREENAPP` от оболочки,
плюс WinEvent `EVENT_SYSTEM_FOREGROUND` и `SHQueryUserNotificationState` (D3D, презентация). Развёрнутое
окно (`IsZoomed`) полноэкранным не считается: при автоскрытии панели задач оно тоже закрывает весь
монитор, но это обычная работа, а не игра или видео.

## D-019. Горячая клавиша может быть занята
`Ctrl+Alt+Space` по умолчанию (как в постановке), но её может держать другое приложение (например,
Quick Entry в Claude Desktop). `RegisterHotKey` тогда возвращает ошибку: остров показывает тихое
уведомление в трее и продолжает работать по наведению; клавиша меняется в настройках.

## D-020. Камера и микрофон — реестр ConsentStore плюс проверка процесса
Приложение «использует» устройство, если `LastUsedTimeStart != 0` и `LastUsedTimeStop == 0`. Аварийно
завершённое desktop-приложение никогда не пишет `LastUsedTimeStop`, и запись «зависает» (на машине
разработчика так висел OBS). Поэтому записи из `NonPackaged` учитываются, только пока жив процесс
с этим exe. Слежение — `RegNotifyChangeKeyValue` с `REG_NOTIFY_THREAD_AGNOSTIC`, без опроса.

## D-021. Live-активности — один арбитр с гистерезисом
Модули публикуют `LiveActivity`, `LiveActivityArbiter` выбирает главную (алерты → приоритет → свежесть)
и вторую (мини-иконка). Главная меняется не чаще раза в 1,5 с, кроме алертов. Индикаторы приватности —
не активности, а точки поверх любого состояния.

## D-022. Восстановление трека — только по нажатию Play и только безопасными путями
После перезагрузки остров показывает сохранённый трек на паузе и ничего не включает сам. По Play:
сессия есть → play + seek; нет → запуск приложения одним из трёх путей: `shell:AppsFolder\<AUMID>`
(Store-приложения и всё, что есть в меню «Пуск», например Яндекс Музыка `ru.yandex.desktop.music`),
зарегистрированный протокол (`spotify:`, `yandexmusic:`), exe из `App Paths`. AUMID проверяется
(без путей, кавычек и спецсимволов) и передаётся одним аргументом, не через командную строку.
Ждём сессию до 15 с, перематываем, только если приложение открыло тот же трек. Браузеры не
запускаются: они не умеют сами вернуть вкладку — показываем подсказку. Обложки кэшируются по
SHA-256, имя файла строго валидируется при чтении.

## D-023. Shelf — каждая копия в своей папке, имена санитизируются
Файл кладётся в `Shelf\items\<guid>\<безопасное имя>`: путь от источника не используется (берётся
только последний сегмент), запрещённые символы и зарезервированные имена Windows (`CON`, `COM1`…)
обезвреживаются, длина ограничена. Отображаемые имена уникальны (`name (2).ext`), чтобы при
вытаскивании нескольких файлов в одну папку не было конфликтов. Папки копируются без перехода по
junction/symlink. Индекс с путями вне папки Shelf при загрузке отбрасывается.

## D-024. Перетаскивание к острову — «ловушка» вместо глобального хука мыши
Прозрачные пиксели layered-окна не получают OLE-drag. Пока зажата левая кнопка и курсор у верхнего
края возле острова (опрос `GetAsyncKeyState`/`GetCursorPos` 4 раза в секунду, только если Shelf
включён), окну даётся почти прозрачный фон (alpha 1/255) — тогда приходит `DragEnter`, и остров
раскрывается в зону сброса. Низкоуровневый хук мыши не нужен.

## D-025. Виртуальные файлы — только первый
WPF отдаёт из `FileContents` только первый поток, поэтому из письма/браузера с несколькими
«виртуальными» файлами берётся первый. Это указано в README.

## D-026. Установщик и обновления — Velopack, packId `DynamicIslandForWindows`
Velopack ставит приложение в `%LOCALAPPDATA%\DynamicIslandForWindows\current` без прав администратора,
обновляется дельтами из GitHub Releases и применяет обновление при выходе. packId отличается от папки
данных (`%LOCALAPPDATA%\DynamicIsland`), поэтому удаление программы не трогает данные пользователя.
При удалении снимается значение автозапуска. Автозапуск включается по умолчанию только у установленной
копии (рядом есть `Update.exe`), чтобы сборка разработчика никогда не прописывала себя в автозагрузку.
Сборка self-contained + ReadyToRun: ≈95 МБ установщик, быстрый старт, не нужен установленный .NET.

## D-027. Без подписи кода в v0.1.0
Сертификата нет; SmartScreen предупреждает, это описано в README. Целостность обновлений держится на
HTTPS GitHub и хешах в `releases.*.json`. Подпись — после появления сертификата (хранить только в Secrets).

## D-028. Размер острова −17 % через общий масштаб
По отзыву на v0.1.0 остров уменьшен примерно на 17 %. Меняется не раскладка, а масштаб по умолчанию
(`IslandScale` 1.0 → 0.83): весь остров — форма, радиусы, плечи, текст и страницы — масштабируется
одинаково, поэтому пропорции сохраняются. Миграция схемы 1 → 2 переводит на новый размер только тех,
у кого стоял старый размер по умолчанию; свой выбор пользователя не трогается. Диапазон в настройках 70–130 %.

## D-029. Вкладка браузера — WinEvent, без опроса
Заголовок активной вкладки берётся из заголовка окна браузера на переднем плане (`GetWindowText`). Хук
`EVENT_SYSTEM_FOREGROUND` на смену окна и, только пока впереди браузер, `EVENT_OBJECT_NAMECHANGE`,
ограниченный процессом этого браузера (переключение вкладки переименовывает окно). Суффиксы
«— Google Chrome», «Microsoft Edge», «Яндекс Браузер», «Mozilla Firefox», «and N more pages» убираются;
для других приложений строка не показывается. Пока впереди окно самого острова, показывается последний
браузер (остров не забирает фокус, но окно настроек может).

## D-030. Имена приложений в индикаторах
Для desktop-приложения — `ProductName`/`FileDescription` из exe (путь из ключа `NonPackaged`), для
Store-приложения — `DisplayName` пакета (`PackageManager.FindPackagesForUser`), раньше обоих — словарь
популярных приложений (Discord, Telegram, Zoom, Teams, Яндекс Браузер, OBS, Chrome…). Компоненты Windows
(`windows.immersive*`, `Microsoft.Windows.*`, `MicrosoftWindows.*`, exe из папки Windows) показываются как
«Системное приложение». Результаты кешируются по ключу.

## D-031. Индикаторы приватности v0.2.0: живой сигнал микрофона, проверка камеры, показ экрана
- **Микрофон — Core Audio.** Активная capture-сессия на любом микрофоне = микрофон используется
  (имя — по PID сессии). Это «правда»: точка гаснет, как только приложение закрыло поток, даже если
  ConsentStore не записал время остановки. ConsentStore используется, только если Core Audio недоступен.
- **Камера — ConsentStore** (публичного API «камера занята» нет), плюс перепроверка раз в секунду,
  пока точка горит, и проверка, что процесс desktop-приложения жив. В простое таймера нет.
- **Показ/запись экрана (красный) — эвристика.** API «кто-то захватывает экран» в Windows нет. Раз в 3 с
  проверяются видимые окна только у браузеров, Zoom и Teams: плашка «…is sharing your screen» /
  «…показывает ваш экран» (Chrome, Edge, Яндекс, Opera, Brave, Vivaldi — Meet, Телемост и любые сайты),
  тулбар демонстрации Zoom, «Sharing control bar» Teams. Раз в 15 с — процесс `bcastdvr` (запись Game Bar).
  OBS/ShareX остаются в отдельной опции «по запущенным программам». **Не определяется:** стрим Discord
  (у него нет отдельного окна-индикатора), захват через DXGI/GDI в произвольных программах.
- Порядок точек: показ экрана → камера → микрофон. Цвета: красный, красный, оранжевый.
- Нагрузка в простое после изменений: 0,44 % одного ядра (было 0,08 %), основная часть — проверка окон.

## D-032. Ввод текста в острове: надёжный захват клавиатуры
В v0.1.0 текст в поле задачи «не было видно», Enter не работал. Причины: (1) высота поля 30 при вертикальных
отступах 6+6 обрезала строку; (2) `SetForegroundWindow` из неактивирующего окна Windows может отклонить
(foreground lock) — тогда нажатия уходили в другое окно. Исправление: отступы поля, `MinHeight` вместо
`Height`; захват переднего плана через `AttachThreadInput` к потоку текущего активного окна на время вызова
(`BringWindowToTop` + `SetForegroundWindow` + `SetFocus`). Проверено вживую через UI Automation: после
«Добавить» остров на переднем плане, фокус в поле, Enter создаёт задачу в `todos.json`, Esc возвращает
`WS_EX_NOACTIVATE`. Shift+Enter переносит строку (до 5 строк). Файл переименован в `todos.json`, старый
`todo.json` переносится один раз.

## D-033. Зависание при наведении — причины и исправление
Корень — обратная связь hit-test: наведение определялось по анимируемой геометрии острова; при
сворачивании форма «уходила» из-под курсора → Leave → Enter → снова раскрытие. Плюс «залипший» DropTarget
после отменённого перетаскивания и случайное закрепление кликом по содержимому страницы.
Исправления: невидимая зона наведения размером с ЦЕЛЕВОЕ состояние (не с анимацией) + 4 px; явная фаза
наведения в машине состояний (`Idle → ExpandPending → Expanded → CollapsePending`), повторный Enter не
перезапускает задержку; страховочный выход из DropTarget (нет кнопки и DragOver 0,5 с); закрепление только
кликом по «хрому» острова (пилюля, шапка). В скрытом режиме зона наведения убирается полностью.
Стресс-тест: 500 случайных Enter/Leave с разными интервалами — остров всегда возвращается в покой.

## D-034. Диктофон — отдельный модуль на NAudio
`WaveIn` (44,1 кГц, моно, 16 бит, буферы по 50 мс) пишет во временный WAV в папке записей; пауза не
закрывает устройство, а перестаёт писать — продолжение мгновенное. При остановке файл сохраняется как WAV
или кодируется в MP3 через Windows Media Foundation; если кодера MP3 нет (редакции Windows «N» без Media
Feature Pack), запись честно остаётся в WAV с подсказкой. Папка по умолчанию — `Музыка\DynamicIsland`.
Модуль удаляет только свои файлы (префикс `Recording `, внутри папки записей). Во время записи — live-пилюля
с красной точкой и таймером; полоски — по реальному пиковому уровню микрофона. Индикатор микрофона
загорается сам: остров открывает capture-поток, и его видит Core Audio, как у любого приложения.

## D-035. Страница «Инструменты»: CPU, FPS, история уведомлений
CPU — общая загрузка по разнице `GetSystemTimes` (те же числа, что в диспетчере задач, без счётчиков
производительности); опрос раз в секунду и только пока остров раскрыт. Цвет: < 50 % зелёный, 50–80 %
жёлтый, ≥ 80 % красный. FPS — только самого острова: средний FPS и самый долгий кадр последней анимации
(`IslandRenderStats`); постоянный счётчик кадров держал бы рендер-цикл включённым и сам грузил бы систему.
История уведомлений — `UserNotificationListener`. Windows отдаёт её только приложениям с идентичностью
пакета (MSIX и capability `userNotificationListener` в манифесте); установка через Velopack такой
идентичности не имеет. Поэтому перед запросом проверяется `GetCurrentPackageFullName`, и без пакета
страница честно пишет, что история недоступна, — без подделок через чтение базы уведомлений Windows
(`wpndatabase.db`: недокументированный формат, приватные данные других приложений). Запрос разрешения
ограничен 10 с. «Очистить» очищает только список на странице, центр уведомлений Windows не трогается.
Путь к полноценной истории — MSIX-сборка (sparse package), отложено: нужна подпись сертификатом.

## D-036. Позиция последнего трека после перезагрузки
Причина «0:03»: после перезагрузки плеер возвращался с тем же треком на 0:00, остров видел «новую» сессию
и сохранял её поверх файла; позицию к тому же досчитывал от устаревшей отметки времени (отсюда 3 с). При
выходе плеер сначала сообщал Stopped на 0, а потом выход острова принудительно сохранял этот ноль.
Решение в `LastTrackStore`: состояние Stopped не сохраняется никогда (позиция у него бессмысленна), а после
загрузки сохранённого трека включается защита: тот же трек с меньшей позицией не перезаписывает файл,
пока трек не дойдёт до сохранённой позиции (или пользователь не перемотает дальше), не проиграет 10 с
подряд или не сменится на другой. Файл читается при каждом запуске, даже если плеер уже открыт, — иначе
защита не включится. Сохранения пишутся в журнал (причина, состояние, позиция; без названий треков).

## D-037. Ревью v0.2.0 (code-reviewer + security-reviewer)
Критичных замечаний нет. Исправлено:
- **Диктофон.** Неудачный старт (нет микрофона) больше не оставляет открытое устройство и файл — следующая
  попытка стартует чисто. Сырой звук пишется в закрытую папку `%LOCALAPPDATA%\DynamicIsland\recorder-temp`,
  а не в папку записей (она может синхронизироваться с облаком); недописанный файл после сбоя при следующем
  запуске восстанавливается как WAV. Недописанный MP3 удаляется, WAV получает уникальное имя. Плеер
  отпускает файл после окончания, «старое» событие остановки не сбрасывает новый трек; неудачное удаление
  показывается. Удаляются только `.wav`/`.mp3` с префиксом `Recording ` прямо в папке записей и не ссылки.
  Папка записей из настроек принимается только локальная, не корень диска, не Windows/Program Files и не
  junction; сетевые пути отвергаются (зависание и утечка учётных данных NTLM).
- **Наведение.** Если полноэкранный режим начался во время задержки раскрытия, фаза сбрасывается — после
  выхода из полноэкранного режима наведение снова раскрывает остров.
- **Последний трек.** Ошибка записи файла не повторяется на каждом событии, а ждёт следующего изменения/периода.
- **Индикаторы.** Проверки по таймерам выполняются по одной (lock), таймер не создаётся после Dispose;
  вкладка браузера не мигает при кратком отсутствии окна переднего плана.
- **Уведомления.** Тайм-аут запроса доступа не блокирует кнопку навсегда.
- **FPS** считается по интервалам (N − 1), а не по кадрам.
Оставлено осознанно: `media-lasttrack.json` хранит название трека открытым текстом (нужно для показа после
перезагрузки; описано в README → Privacy); последние ≤ 50 мс записи при остановке могут не попасть в файл.
